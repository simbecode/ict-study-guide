📐 서브넷 마스크 한눈에

IPv4 주소는 32비트다. /n 은 앞 n비트가 네트워크, 나머지 32−n비트가 호스트라는 뜻이다.
마스크는 네트워크 부분을 1, 호스트 부분을 0으로 채운 값이고, 1은 항상 왼쪽부터 이어진다.
사용 가능 호스트 = 2호스트 비트 − 2 (네트워크 주소·브로드캐스트 주소 제외). /n이 1 커지면 주소 수는 절반이 된다.

• /24 ~ /30 7줄부터 외운다. 마지막 옥텟만 바뀌어 계산이 가장 쉽다.
• 블록 간격 = 256 − 마스크 값 (예: /27 → 256 − 224 = 32). /23처럼 셋째 옥텟에 걸리면 셋째 옥텟 기준으로 센다 (256 − 254 = 2).
• /31은 점대점 링크용으로 주소 2개를 모두 쓰고, /32는 단일 호스트 주소다. 둘 다 −2 공식을 쓰지 않는다.
⭐ 마지막 옥텟 암기법

비트 가중치를 왼쪽부터 더한다

128 · 64 · 32 · 16 · 8 · 4 · 2 · 1
↓ 누적 합 = 마스크 값
128 → 192 → 224 → 240
→ 248 → 252 → 254 → 255

/25 ~ /30 은 세 줄을 짝으로

마스크  128 · 192 · 224 · 240 · 248 · 252
주소 수 128 ·  64 ·  32 ·  16 ·   8 ·   4
호스트 126 ·  62 ·  30 ·  14 ·   6 ·   2

예: /27 = 24 + 3 → 255.255.255.11100000 = 255.255.255.224 → 블록 간격 256 − 224 = 32 → 마지막 옥텟 시작값 0 · 32 · 64 · 96 · 128 · 160 · 192 · 224
🧩 그림으로 보는 서브넷팅
📝 계산 순서 — 192.168.10.77/27
① 마스크·간격 /27 → 255.255.255.224, 256 − 224 = 32 ② 들어갈 블록 77은 64 이상 96 미만 → ⌊77 ÷ 32⌋ × 32 = 64 ③ 시작과 끝 네트워크 192.168.10.64 / 브로드캐스트 192.168.10.95 (다음 시작 96 − 1) ④ 호스트 범위 192.168.10.65 ~ 94 → 32 − 2 = 30개

/23처럼 옥텟을 넘으면

192.168.11.77/23 → 마스크 255.255.254.0
셋째 옥텟 간격 256 − 254 = 2 → 10·11이 한 블록
네트워크 192.168.10.0 · 브로드캐스트 192.168.11.255

서브넷 개수와 호스트 수는 다르다

/24를 /27로 나누면 빌린 비트 3개 → 서브넷 2³ = 8개
서브넷마다 호스트 비트 5개 → 호스트 2⁵ − 2 = 30개
개수는 빌린 비트, 호스트는 남은 비트로 센다.

⏱️ 10초 확인
확인 1호스트 50대가 필요할 때 가장 작은 서브넷은?
2⁵ − 2 = 30 → 부족, 2⁶ − 2 = 62 → 충분 → 호스트 비트 6 → 32 − 6 = /26
정답 /26 (255.255.255.192)
확인 2192.168.1.130/26의 네트워크 주소와 브로드캐스트 주소는?
간격 256 − 192 = 64 → 블록 128 ~ 191 → 호스트 .129 ~ .190
정답 192.168.1.128 / 192.168.1.191
확인 3/24를 /28로 나누면 서브넷 몇 개, 서브넷당 호스트 몇 개?
빌린 비트 4 → 2⁴ = 16개, 남은 호스트 비트 4 → 2⁴ − 2 = 14
정답 16개 / 14개
⚠️ 자주 틀리는 곳
• 256 − 마스크 값은 그 옥텟의 간격이지 전체 주소 수가 아니다. /23의 전체 주소는 2가 아니라 512개다.
• 호스트 수를 물으면 −2를 잊지 않는다. 32개로 답하면 오답이다.
• 클래스 판별(첫 옥텟)과 마스크 비트는 다른 이야기다 → IP 클래스 · 서브넷마스크 · CIDR
