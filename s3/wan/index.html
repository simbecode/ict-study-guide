📖 T1이 1.544 Mbps인 이유 — 유도 과정이 그대로 출제된다
① 음성 4kHz → 표본화 8kHz, 8비트 부호화 → 채널당 64 kbps
② 24채널 × 8비트 = 192비트 + 프레임 동기 1비트 = 193비트/프레임
③ 193비트 × 8,000프레임/초 = 1,544,000 bps = 1.544 Mbps
E1 = 32 × 8 × 8,000 = 2.048 Mbps (동기비트 없이 슬롯 0을 동기용으로 씀)

🧠 부호화 법칙 — 「A는 유럽, μ는 미국」
　A-law (A = 87.6) → E1 · 유럽 · 압축 특성 13절선
　μ-law (μ = 255) → T1 · 북미(미국·일본) · 압축 특성 15절선
μ는 255, A는 87.6 — 숫자가 그대로 보기로 나온다. 절선 수는 13(A) · 15(μ) 로, 알파벳 순서 A → μ 가 13 → 15 로 커진다고 묶어 외운다.
⚠️ 가장 많이 틀리는 곳 — T1의 「채널당 56 kbps」
T1도 물리적으로는 64 kbps 슬롯이다. 그런데 신호(시그널링)를 위해 각 채널의 8번째 비트를 6프레임마다 빌려 쓰기(로버드 비트) 때문에, 실제 데이터로 쓸 수 있는 것은 7비트 × 8k = 56 kbps 가 된다.
E1은 16번 슬롯을 통째로 신호용으로 따로 떼어 놓아서, 데이터 채널은 온전히 64 kbps 를 쓴다.
→ "신호를 어디서 실어 나르는가" 하나가 56 / 64 의 차이를 만든다.
E1 프레임 (32 슬롯) ┌────┬──────────────────┬────┬──────────────────┐ │ 0 │ 1 ~ 15 (음성) │ 16 │ 17 ~ 31 (음성) │ └────┴──────────────────┴────┴──────────────────┘ 동기용 신호용 → 음성 30채널 T1 프레임 (24 슬롯 + 동기 1bit) ┌─┬──────────────────────────────────────┐ │F│ 1 ~ 24 (음성, 각 8bit) │ └─┴──────────────────────────────────────┘ 동기 1bit → 음성 24채널 ※ 각 채널의 8번째 비트를 주기적으로 신호용으로 빌려 씀
🧠 숫자를 외우지 말고 계산한다
　E1 = 32슬롯 × 8bit × 8,000 = 2,048,000 = 2.048 Mbps
　T1 = (24 × 8 + 1) × 8,000 = 193 × 8,000 = 1,544,000 = 1.544 Mbps
T1에만 +1(프레임 동기 비트)이 붙는 것만 기억하면 둘 다 나온다. 양쪽 모두 초당 8,000 프레임(표본화 주파수와 같다)이다.
