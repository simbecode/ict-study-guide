CIDR /n
IPv4는 32비트. 앞 n비트는 네트워크, 나머지 32−n비트는 호스트입니다.
마스크의 1과 0
네트워크 부분은 1, 호스트 부분은 0. 1은 왼쪽부터 연속됩니다.
일반 서브넷의 사용 가능 호스트
2호스트 비트 수 − 2
네트워크 주소와 브로드캐스트 주소를 제외합니다. /31·/32는 예외입니다.

블록 간격은 표시된 옥텟에서 네트워크 시작 값이 증가하는 폭입니다. /24는 마지막 옥텟 전체(0~255)가 한 블록입니다. /31은 점대점 링크에서 두 주소를 사용하고, /32는 단일 호스트 주소·경로를 나타냅니다.

마지막 한 옥텟은 이 순서로 외우세요

왼쪽부터 더하면 마스크 값이 됩니다.
마스크 값
0 → 128 → 192 → 224 → 240 → 248 → 252 → 254 → 255
1의 개수: 0 → 1 → 2 → 3 → 4 → 5 → 6 → 7 → 8
/25부터 /30까지 짝으로 암기
마스크: 128 · 192 · 224 · 240 · 248 · 252
주소 수: 128 · 64 · 32 · 16 · 8 · 4
호스트 수: 126 · 62 · 30 · 14 · 6 · 2
예: /27 = 24 + 3 → 255.255.255.11100000 → 255.255.255.224
블록 간격 = 256 − 224 = 32 → 마지막 옥텟의 시작 값은 0, 32, 64, 96, 128, 160, 192, 224.

192.168.10.77/27 — 네트워크·브로드캐스트 찾기

① 마스크와 간격/27 → 255.255.255.224
256 − 224 = 32
② 포함되는 블록77은 64 이상, 96 미만
⌊77 ÷ 32⌋ × 32 = 64
③ 시작과 끝네트워크: 192.168.10.64
브로드캐스트: 192.168.10.95 (다음 시작 96 − 1)
④ 호스트 범위192.168.10.65~94
전체 32개 − 2 = 30개
정확한 계산 원리
IP 주소 AND 서브넷 마스크 = 네트워크 주소.
호스트 비트를 전부 1로 바꾸면 브로드캐스트 주소입니다.
/23처럼 옥텟을 넘으면?
192.168.11.77/23 → 마스크 255.255.254.0.
세 번째 옥텟 간격 2 → 네트워크 192.168.10.0, 브로드캐스트 192.168.11.255.
서브넷 개수와 호스트 수는 다릅니다
/24를 /27로 나누면 빌린 비트는 3개 → 서브넷 2³ = 8개. 각 서브넷의 사용 가능 호스트는 2⁵ − 2 = 30개입니다.

10초 확인 — 먼저 답을 떠올려 보세요

호스트 50대가 필요할 때 가장 작은 서브넷은?

/26. 2⁵ − 2 = 30은 부족하고, 2⁶ − 2 = 62는 충분합니다. 마스크는 255.255.255.192입니다.

192.168.1.130/26의 네트워크와 브로드캐스트는?

간격 64 → 128~191 블록. 네트워크는 192.168.1.128, 브로드캐스트는 192.168.1.191, 호스트는 192.168.1.129~190입니다.

/24를 /28로 나누면 서브넷 몇 개, 호스트 몇 개?

빌린 비트 4개 → 서브넷 16개. 서브넷마다 전체 주소 16개, 사용 가능 호스트 14개입니다.

주의: 256 − 마스크 값은 해당 옥텟의 간격입니다. /23의 전체 주소 수는 2가 아니라 512개입니다. 클래스 A·B·C의 기본 마스크와 실제로 주어진 CIDR도 구분하세요.
