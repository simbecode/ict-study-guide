🛰️ 네트워크 관리 — SNMP · MIB · SMI · RMON

4과목에서 매 회차 2~3문항이 이 한 주제에서 나온다. 구조는 단순하다 — 관리자(Manager)가 에이전트(Agent)에게 물어보고, 에이전트는 MIB라는 장부를 보고 답한다. 그 대화에 쓰는 말이 SNMP, 장부 쓰는 법을 정한 문법이 SMI다.

장애 · 구성 · 계정 · 성능 · 보안. 영문 머리글자로는 FCAPS. 보기에 "설계관리 · 개발관리 · 영업관리" 같은 게 섞여 나오면 그게 답(아닌 것)이다 — 망관리는 이미 깔린 망을 돌보는 일이지, 만드는 일이 아니다.

⚠️ 기출 함정 — 「MIB에 저장된 객체 값은 읽기 전용이다」는 틀린 설명
MIB 객체는 읽기(Get)도 쓰기(Set)도 가능하다. 접근 속성이 read-only인 객체도 있지만, MIB 전체가 읽기 전용이라는 진술은 오답이다. 2022-1회 69번에서 이 보기가 정답(틀린 것)으로 나왔다.
📮 SNMP 메시지(PDU) 5종 — v1 기준
PDU방향의미
Get-RequestM → A지정한 OID 하나의 값을 달라
GetNext-RequestM → A지정 OID의 다음 객체를 달라 — 트리를 순회(walk)할 때 사용
Set-RequestM → A객체 값을 바꿔라 — 유일한 쓰기 명령
Get-ResponseA → M위 세 요청에 대한 응답
TrapA → M사건이 생기면 에이전트가 먼저 알린다 — 유일한 비요청(unsolicited) 메시지
🧠 포트 암기 — 「평소엔 161, 사고 나면 162」
UDP 161 = Agent가 열어놓고 질문을 받는 문. UDP 162 = Manager가 열어놓고 Trap을 받는 문. Trap만 번호가 하나 크다고 외우면 된다.
왜 UDP인가 — 망이 아플 때도 가벼워야 하고, 관리 트래픽이 망을 더 막으면 안 되기 때문. 대신 신뢰성이 없어서 Trap은 유실될 수 있다(v2의 Inform이 이를 보완).
🔢 SNMP 버전 비교
버전인증 방식추가된 것한계
v1커뮤니티 스트링 (평문 문자열, 기본값 public/private)기본 5개 PDU평문 전송 → 도청 취약
v2c커뮤니티 스트링 (v1과 동일)GetBulk(대량 조회) · Inform(응답받는 Trap) · 64비트 카운터보안은 v1과 같음
v3USM — 사용자 기반 인증 + 암호화인증·암호화·무결성·접근제어(VACM)설정이 복잡
한 줄 정리 — v1은 기능, v2c는 성능(GetBulk), v3는 보안. "SNMP에 보안을 추가한 버전은?" → v3. "대량의 데이터를 한 번에 가져오는 명령은?" → GetBulk(v2c).
🌳 MIB 트리와 OID
root └─ iso (1) └─ org (3) └─ dod (6) └─ internet (1) ├─ directory (1) ├─ mgmt (2) ─── mib-2 (1) ── system(1) interfaces(2) ip(4) tcp(6) udp(7) … ├─ experimental (3) └─ private (4) ─ enterprises (1) ── 벤더별 고유 MIB MIB-II 의 OID 시작 = 1.3.6.1.2.1 (RFC 1213) 벤더 고유 MIB 시작 = 1.3.6.1.4.1
🧠 「1.3.6.1」은 무조건 외운다 — iso(1)·org(3)·dod(6)·internet(1). 뒤에 2.1이면 표준 MIB-II, 4.1이면 벤더 사설 MIB. MIB-II = RFC 1213, SMI = ASN.1 표기법, 전송 시 인코딩은 BER.
📡 RMON — 원격 모니터링
구분감시 계층보는 것
RMON 11~2계층 (물리·데이터링크)세그먼트 트래픽 통계, 이더넷 프레임, 알람·이벤트
RMON 23~7계층 (네트워크~응용)프로토콜별·호스트별·응용별 트래픽 분석
SNMP는 "물어봐야 답하는" 방식이라 Manager가 계속 폴링하면 망에 부하가 걸린다. RMON은 프로브(probe)가 현장에서 스스로 통계를 모아뒀다가 요약해서 넘긴다 — 폴링 트래픽을 줄이는 것이 목적.
