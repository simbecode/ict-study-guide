🏢 배치(구축) 모델
모델내용특징
퍼블릭 (공용)불특정 다수가 공유하는 클라우드비용 저렴, 확장 쉬움 / 보안·규제 제약
프라이빗 (사설)특정 조직 전용보안·통제 우수 / 구축비 높음
하이브리드퍼블릭 + 프라이빗 결합민감 데이터는 사설, 일반 업무는 공용 (가장 현실적)
커뮤니티같은 목적의 여러 조직이 공동 사용공공기관·의료기관 연합 등
멀티클라우드여러 사업자의 클라우드를 동시에 사용특정 벤더 종속(Lock-in) 회피
⚠ 기출 함정 — "SaaS : 공용 클라우드 서비스" → 틀림. SaaS는 서비스 모델(무엇을 제공하는가) 이고, 퍼블릭/프라이빗은 배치 모델(어디에 두는가) 이다. 서로 다른 분류 축이다.

Scale-Up (수직 확장)

한 대의 성능을 올림
CPU·메모리 업그레이드

한계가 있고 비용이 급증

Scale-Out (수평 확장)

서버 대수를 늘림
분산 처리·로드밸런싱

클라우드가 잘하는 방식

⚠ 기출 함정 — "수평적 성능 확대는 통신회선을 높은 대역으로 업그레이드하는 것" → 틀림. 회선 업그레이드는 수직 확장(Scale-Up) 에 가깝다. 수평 확장은 서버 수를 늘리는 것.
⚖ 클라우드 · 가상화의 이점과 한계

✅ 이점

• 초기 구축 비용 절감 (CapEx → OpEx)
• 사용한 만큼만 과금
• 빠른 배포와 유연한 확장
• 자원 효율·생산성 향상
• 재해 복구(DR) 용이

⚠ 한계

• 네트워크 장애 시 업무 전면 중단
• 데이터 보안·주권·규제 문제
• 벤더 종속(Lock-in)
• 장기 사용 시 비용이 더 클 수 있음

⚠ 기출 함정 — 클라우드 가상화의 이점으로 "정합성(Integrity) 향상" 은 해당하지 않는다. 이점은 비용 절감 · 효율성 · 재해복구 · 빠른 배포 · 유연성이다.
클라우드 보안 — Governance(관리방식) 영역 기출
컴플라이언스/감사 · 정보관리/데이터 보안 · 이식성/상호운영성이 Governance 영역이고, 애플리케이션 보안은 여기에 포함되지 않는다(운영 영역).
📝 시험 포인트
• IaaS = 인프라(서버·스토리지·네트워크), PaaS = 개발 플랫폼, SaaS = 완성된 소프트웨어
• 사용자 관리 범위: IaaS(OS부터) > PaaS(데이터·앱) > SaaS(설정만)
• BPaaS는 비즈니스 프로세스 — 컴퓨팅 리소스 제공은 IaaS
• SaaS ≠ 공용 클라우드 — 서비스 모델과 배치 모델은 다른 축
• Scale-Out = 서버 수 증가(수평), Scale-Up = 단일 서버 성능 향상(수직)
• 가상화 이점에 정합성 향상은 없다
• 대표 SaaS = Gmail · Office 365, 대표 IaaS = AWS EC2
